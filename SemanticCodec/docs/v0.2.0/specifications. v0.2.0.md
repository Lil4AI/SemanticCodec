# Semantic Codec v0.2.0 仕様書 (Final)

本ドキュメントは、v0.2.0で完了したアーキテクチャの大幅なアップデートと技術的制約、および次期バージョンへ持ち越される既知のバグを定義します。

## 1. 強化された `.semic.jpg` フォーマット (Polyglotアーキテクチャ)
v0.2.0より、生成されるファイルは純粋なZIPではなく**「JPEG + ZIP」の結合バイナリファイル**となりました。
- **データ構造**:
  `[先行する JPEG ヘッダと軽量プレビュー用画像データ]` + `[後行する ZIP アーカイブ配列 (マニフェスト, 前景WebP, Canny等)]`
- **利点と挙動**: 
  - OSの画像ビューワ（Windowsフォト、エクスプローラ）はファイルの先頭からJPEGの終端記号までを読み取ってサムネイルを即座に表示します。
  - 本アプリのデコーダ（Python `zipfile` ライブラリ）はファイルの末尾からZIPディレクトリ構造を検索するため、JPEGの後ろのバイナリを完全に解凍できます。
  - これにより、専用の拡張機能がなくても**「中身が見える圧縮ファイル」**を実現しました。

## 2. LoRA によるスタイライズデコード (Stylized Decode)
背景展開時に、特定の画風や空間を再現するための LoRA (\*.safetensors) を動的に注入するシステムです。
- ユーザーがUIからLoRAのファイル名（`loras/` フォルダ内）と適用強度（`0.0 ~ 2.0`）を指定し、`manifest.json` に記録します。
- **フォールバック機構**: デコード側のPCに該当するLoRAが存在しなかったり、SD1.5非対応（FLUX用やSDXL用）モデルでエラーが出た場合は、安全装置（try-except）が働き、警告を出力して標準モデルによる再構築へ自動移行します。

## 3. プロンプト生成エンジンの改良
SD-Inpaintingモデルが背景を正確に再構築できるよう、BLIPモデルが抽出する情報とプロンプトパラメータを強化しました。
- 画像全体からキャプションを生成し、システム側で `, background environment, scenery, masterpiece, photorealistic, highly detailed, 8k resolution, sharp focus` を強制結合します。
- デコード時の再構築強度（`strength`）を `1.0` (100%ノイズからの完全再構築) とすることで、サムネイルのブロックノイズやガウスブラーの残りを除去し、超解像での復元を可能にしました。

## 4. 📉 既知のバグ・制限事項 (Known Issues)
v0.2.0 クローズ時点において、以下の現象が確認されており、次期バージョン（v0.3.0）以降での解決課題とします。

### バグA: HighFi モードにおけるテクスチャの暴走・浸食
**【事象】**
HighFi（ControlNet + Canny）でデコードすると、背景が「特定のテクスチャ（馬の肌など）」で埋め尽くされてしまう現象。Standardモードでは発生しない。
**【原因推測】**
Canny特徴抽出（元の画像の輪郭線）をガイドとして渡しつつ、デコード強度を `1.0` に引き上げたことで、**「前景オブジェクトの輪郭線までもが背景領域のノイズとして解釈」**されてしまい、プロンプトの特定のキーワードに乗っ取られてControlNetが全体にテクスチャを強制描画してしまっている可能性が高いです。

### バグB: 前景（被写体）境界付近のモザイク抜け落ち
**【事象】**
Foreground（被写体）の切り抜きは綺麗に保存されているが、デコード合成後の結果を見ると、被写体の輪郭線ギリギリの外側に元のサムネイルの「モザイクやブラーの抜け落ち・粗い部分」が薄く残って見える現象。
**【原因推測】**
RemBGで生成されたAlphaマップをそのまま Invert してマスク（Inpaint対象領域）にしていますが、エッジ領域（半透明ピクセル部分など）がInpaint領域として完全にカバーされておらず、AIが塗らなかった数ピクセルの「元画像の粗いままの領域」が境界線の外側に残ってしまっていると考えられます。マスクの膨張処理（Dilation）を加えることで解決できる見込みです。
