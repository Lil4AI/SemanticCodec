# Semantic Codec v0.2.0 実装計画書

## 概要と目標
v0.1.0 で実現した「画像のセマンティック圧縮（前景ロスレス+背景AI再構成）」の基本パイプラインに対し、v0.2.0ではさらに実用性と表現力を高める以下の2大機能を追加実装します。

## 提案する新機能
1. **ポリグロットファイル（画像擬態）ハックの導入**
   - **目的**: OSのエクスプローラー上で、専用の拡張機能なしでも `.semic` が「普通の画像」としてサムネイル表示されるようにする。
   - **実装方針**: 
     現在の単なるZIPファイルではなく、「先頭に `thumb.jpg` (または合成プレビュー画像) のJPEGバイナリを配置し、その後ろに本来のZIPデータを結合する」アプローチを採用します。Pythonの `zipfile` やその他多くのZIPパーサーはファイルの末尾からディレクトリを検索するため、JPEGの後ろに結合されていてもそのままデコード可能です。
     
2. **LoRA (Low-Rank Adaptation) の動的適用**
   - **目的**: 背景展開時に「水彩画風」「サイバーパンク風」など、任意のLoRAモデルを適用して展開出力できるようにする。
   - **実装方針**:
     UI（フロントエンド）にLoRAモデルの入力を追加し、デコードリクエスト時にDiffusers の `load_lora_weights` および `cross_attention_kwargs` を活用して Inpainting パイプラインに画風を注入します。

## 確認事項（User Review Required）
> [!IMPORTANT]
> **1. ポリグロット化時の拡張子について**
> 拡張子は現在の名前のまま `.semic` とし、ユーザーのWindows側で `.semic` の関連付けを画像ソフトにしてもらう方針としますか？ それともいっそファイルを `.semic.jpg` という名前にして出力してしまいますか？
> 
> **2. LoRAモデルの取得元について**
> LoRAモデルはご自身のPCのローカルにある自前のもの（たとえば別のフォルダにある `.safetensors`）を参照するUIがよいか、それとも Hugging Face の既存モデルの名前を入力してダウンロードさせる形式がよいですか？

## 検証プラン (Verification Plan)
- 結合ファイルに対して正しくデコード処理が動き、エラーなくForegroundとメタが抽出できること。
- Windows のエクスプローラ等で出力ファイルの拡張子を `.jpg` にすればサムネイルがプレビューできることの目視確認。
- 指定したLoRAの画風が、HighFiモードの構図を壊さずに背景に乗ること。
