# Semantic Codec - プロジェクト進行・バージョン管理ルール

## 1. バージョニングの定義 (セマンティックバージョニング準拠)
本プロジェクトは `vX.Y.Z` 形式でバージョンを進行します。
- **X (メジャー)**: コアアーキテクチャの根本的な変更、後方互換性のない仕様変更。
- **Y (マイナー)**: 新機能の追加、大きな仕様修正（例：LoRA対応、ポリグロット対応など）。
- **Z (パッチ)**: バグ修正、パフォーマンス最適化（例：FP16の修正など）。

## 2. ドキュメント管理のルール
開発の進捗と歴史を完全にトレース可能にするため、**マイナーバージョン（Y）の更新ごと**に以下の4つのドキュメントを「新しいバージョンの専用ディレクトリ」に分けて作成・保存します。（過去のものを上書きして消さないこと！）

### 必須ドキュメント群:
1. `implementation_plan.md` (実装計画書)：新バージョンで何をどうやって実装するかの設計と課題の計画。
2. `task.md` (タスク・進捗リスト)：計画を実行可能な小タスクに分割したチェックリスト。`[ ]`, `[/]`, `[x]` 等で進捗を可視化する。
3. `walkthrough.md` (作業振り返り)：実装完了後の結果検証・動作確認のレポート。
4. `specifications.md` (仕様書)：そのバージョンにおける全体アーキテクチャやシステム要件・データ構造の最終的な情報。

---
今後は新しいマイナー更新を開始する際、`/docs/v0.2.0/` や `/docs/v0.3.0/` のように、バージョンごとにフォルダを作って上記ドキュメントを蓄積していきます。

## 3. 成果物・検証用データの保存ルール
バージョン毎のテストで生成したデコード結果の出力画像（`.jpg`）やテスト環境での `.semic` ファイルなどのバイナリ成果物は、今後の比較検討のために以下の専用ディレクトリの中に各バージョンのフォルダを作って保管します。
- `outputs/vX.Y.Z/`
